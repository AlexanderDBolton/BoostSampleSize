Drawing, checking, and redrawing until the covariates balance — the Mahalanobis criterion, the acceptance ellipse, how much it buys you, and how to compute it efficiently.

Published

August 24, 2026

You have \(N\) units with covariate matrix \(X\) (\(N \times p\)), and you want to split them into two equal groups of \(n = N/2\) such that the covariates are balanced. The plan is rerandomization: draw a random split, measure imbalance, and redraw if the imbalance is too large.

The measure of imbalance is a Mahalanobis distance. This article assumes the previous one, and in particular that \(D^2 = (x-\mu)^{\top}\Sigma^{-1}(x-\mu)\) is affine invariant, discounts correlated columns rather than double-counting them, and handles categorical covariates via a dropped baseline or a pseudo-inverse.

The criterion

The natural summary of imbalance is the vector of covariate mean differences,

\[ d \;=\; \bar{X}_T - \bar{X}_C \;\in\; \mathbb{R}^p . \]

Under complete randomization into equal halves, \(\mathbb{E}[d] = 0\) and

\[ \operatorname{Cov}(d) = \Big(\tfrac{1}{n_T} + \tfrac{1}{n_C}\Big) S = \frac{4}{N}\,S , \]

where \(S\) is the sample covariance matrix of the covariates. So \(d\) is a random vector with a known mean and a known covariance, and the obvious way to say “\(d\) is too far from zero” is its Mahalanobis distance from \(0\):

\[ M \;=\; d^{\!\top}\big[\operatorname{Cov}(d)\big]^{-1} d \;=\; \frac{N}{4}\; d^{\!\top} S^{-1} d . \]

This is exactly the criterion Morgan and Rubin proposed in 2012. Everything from the Mahalanobis article applies verbatim: \(M\) is affine invariant (so the units of your covariates are irrelevant and you need not standardise first), correlated covariates are not double-counted, and categorical covariates are handled by dropping a baseline or using \(S^{+}\).

Show the code 
N = 200
n_T = N // 2

# Two covariates so the acceptance region can be drawn.
Xrr = rng.multivariate_normal(mu_hw, S_hw, N)
S_rr = np.cov(Xrr, rowvar=False, ddof=1)
cov_d = (4 / N) * S_rr

def draw_splits(B, N, n_T, rng):
    """B random equal splits, as a B x N matrix of +1 (treated) / -1 (control)."""
    idx = np.argsort(rng.random((B, N)), axis=1)[:, :n_T]
    s = -np.ones((B, N))
    np.put_along_axis(s, idx, 1.0, axis=1)
    return s

B = 40_000
s_mat = draw_splits(B, N, n_T, rng)
d_all = (2 / N) * (s_mat @ Xrr)                       # B x 2 mean differences
M_all = np.einsum("bi,ij,bj->b", d_all, np.linalg.inv(cov_d), d_all)

print(f"empirical Cov(d) / theoretical (4/N)S:\n"
      f"{np.round(np.cov(d_all, rowvar=False) / cov_d, 3)}")
print(f"\nmean of M : {M_all.mean():.4f}   (chi-square with p=2 has mean 2)")

Choosing the threshold

Since \(M\) is a squared Mahalanobis distance of an (approximately normal) \(p\)-vector, \(M \sim \chi^2_p\). That gives you the threshold directly. To accept a proportion \(p_a\) of draws, set

\[ a = F^{-1}_{\chi^2_p}(p_a), \qquad \text{accept iff } M \le a . \]

The expected number of draws before acceptance is \(1/p_a\). Note that thresholding \(M\) at \(a\) is the same as thresholding the distance \(\sqrt{M}\) at \(\sqrt{a}\); the squared scale is the convenient one because it is the scale on which the \(\chi^2\) table is written.

Show the code 
rows = []

The acceptance region is an ellipse

For \(p = 2\) you can draw it. The set \(\{d : M(d) \le a\}\) is an ellipse centred at the origin, and its shape is set by \(S\) — it is elongated in exactly the direction in which imbalance naturally occurs.

Show the code 
p_a = 0.05
a_thr = stats.chi2.ppf(p_a, 2)
accept = M_all <= a_thr

sd_d = np.sqrt(np.diag(cov_d))
theta = np.linspace(0, 2 * np.pi, 400)
L_rr = np.linalg.cholesky(cov_d)

def ellipse(a):
    """Boundary {d : M(d) = a} in raw mean-difference units."""
    return (np.sqrt(a) * L_rr @ np.vstack([np.cos(theta), np.sin(theta)])).T

Why an ellipse and not a circle

The ellipse leans along the positive correlation between height and weight, which at first looks backwards: it is more permissive about splits where both covariates are imbalanced in the same direction. That is the correct behaviour, for the same reason correlated columns are not double-counted. Height and weight are correlated at \(0.7\), so a split that over-represents tall people will mechanically over-represent heavy people too. Those two imbalances are largely one imbalance, and a criterion that counted them separately would spend nearly all its rejections fighting the most common failure mode while barely constraining the rare, genuinely informative direction — arms that differ in weight given height.

There is also a practical reason to prefer the ellipse:

The Mahalanobis criterion accepts exactly \(p_a\) of draws whatever the correlation structure is, so you can read the threshold off a \(\chi^2\) table. The per-covariate criterion’s acceptance rate depends on \(S\), so its threshold has to be calibrated by simulation every time.

How much does it buy you?

Morgan and Rubin show that rerandomizing on \(M \le a\) reduces the variance of every covariate mean difference by the same factor,

\[ v_a \;=\; \frac{\operatorname{Var}_{\text{RR}}(d_j)}{\operatorname{Var}_{\text{CR}}(d_j)} \;=\; \frac{P\big(\chi^2_{p+2} \le a\big)}{P\big(\chi^2_{p} \le a\big)} . \]

The important qualitative feature is how it degrades with \(p\): at a fixed acceptance rate, more covariates means less benefit per covariate. Balancing on twenty covariates at \(p_a = 0.01\) buys much less than balancing on two.

Show the code

    v_g = stats.chi2.cdf(a_g, pv + 2) / stats.chi2.cdf(a_g, pv)
    ax.plot(pa_grid, v_g, color=col, lw=2, label=f"$p = {pv}$")

Two caveats keep this honest.

Balance is not the goal; precision is. The variance of the treatment effect estimator is reduced by a factor of \(1 - (1 - v_a)R^2\), where \(R^2\) is the squared multiple correlation between the outcome and the covariates. If your covariates do not predict the outcome, perfect balance on them buys you nothing. Covariate choice matters more than threshold choice.

The usual standard errors no longer apply. Rerandomization makes the sampling distribution of the difference in means non-normal — Li, Ding and Rubin (2018) show it is a normal plus a truncated-normal term. A conventional two-sample \(t\)-test on rerandomized data is conservative (its intervals are too wide). Either use randomization-based inference that redraws under the same rerandomization scheme, or use the asymptotic distribution from that paper.

Doing it efficiently

Inside a rerandomization loop you will evaluate \(M\) hundreds of thousands of times, so it is worth not recomputing anything that does not change. Write \(s_i = +1\) for treated and \(-1\) for control, with \(\sum_i s_i = 0\). Then \(d = \frac{2}{N}\sum_i s_i x_i\), and substituting into \(M\):

\[ M \;=\; \frac{1}{N}\Big\|\sum_{i=1}^{N} s_i z_i\Big\|^2, \qquad z_i = L^{-1}(x_i - \bar{x}), \quad S = LL^{\!\top}. \]

Whiten the covariate matrix once, and every draw afterwards is a sum of rows and a squared norm — no linear solve, no covariance matrix.

Show the code 
Z_rr = np.linalg.solve(np.linalg.cholesky(S_rr), (Xrr - Xrr.mean(0)).T).T
M_fast = np.sum((s_mat @ Z_rr) ** 2, axis=1) / N
print(f"max |M - M_fast| = {np.abs(M_all - M_fast).max():.3e}")
max |M - M_fast| = 1.705e-13

How much does it actually matter? Honest timings on a larger problem (\(N = 400\), \(p = 8\), 20,000 draws), from the naive loop most people write first down to a fully vectorised version:

Show the code 
import time

N_b, p_b, B_b = 400, 8, 20_000
Xb = rng.normal(size=(N_b, p_b)) @ rng.normal(size=(p_b, p_b)) + 3.0
Sb = np.cov(Xb, rowvar=False, ddof=1)
Sb_inv = np.linalg.inv(Sb)
Zb = np.linalg.solve(np.linalg.cholesky(Sb), (Xb - Xb.mean(0)).T).T
nTb = N_b // 2
Zb_tot = Zb.sum(0)

def loop_resolve():
    out = np.empty(B_b)
    for b in range(B_b):
        m = np.zeros(N_b, bool); m[rng.permutation(N_b)[:nTb]] = True
        d = Xb[m].mean(0) - Xb[~m].mean(0)
        out[b] = (N_b / 4) * d @ np.linalg.solve(Sb, d)     # refactorises S!
    return out

def loop_precomputed():
    out = np.empty(B_b)
    for b in range(B_b):
        m = np.zeros(N_b, bool); m[rng.permutation(N_b)[:nTb]] = True
        d = Xb[m].mean(0) - Xb[~m].mean(0)
        out[b] = (N_b / 4) * d @ Sb_inv @ d
    return out

def loop_whitened():
    out = np.empty(B_b)
    for b in range(B_b):
        g = 2 * Zb[rng.permutation(N_b)[:nTb]].sum(0) - Zb_tot
        out[b] = (g @ g) / N_b
    return out

def batched():
    s = draw_splits(B_b, N_b, nTb, rng)
    return np.sum((s @ Zb) ** 2, axis=1) / N_b

timings = []
for name, fn in [("loop, re-solves S each draw", loop_resolve),
                 ("loop, precomputed inverse", loop_precomputed),
                 ("loop, whitened Z", loop_whitened),
                 ("fully vectorised on Z", batched)]:
    t0 = time.perf_counter(); out = fn(); el = time.perf_counter() - t0
    timings.append({"implementation": name, "ms for 20,000 draws": el * 1000,
                    "mean M (should be ~8)": out.mean()})

tdf = pd.DataFrame(timings)
tdf["speed-up"] = tdf["ms for 20,000 draws"].iloc[0] / tdf["ms for 20,000 draws"]
tdf.set_index("implementation").round(2)

The gains are real but moderate, because the dominant cost is forming the mean difference at all — that is \(O(Np)\) per draw no matter what you do. The point of the whitened form is less that it is fast and more that it makes it impossible to accidentally refactorise \(S\) inside the loop.

Practical notes and failure modes

Feasibility at small \(N\). There are only \(\binom{N}{N/2}\) distinct equal splits. That is astronomically large for \(N = 200\), but for \(N = 20\) it is 184,756, and an acceptance rate of \(10^{-6}\) is then not merely slow but impossible. Check \(p_a \binom{N}{N/2} \gg 1\).

More covariates is not free. Adding a correlated covariate does not get it extra weight in \(M\), but it does raise \(p\), which shrinks the variance reduction \(v_a\) available at any acceptance rate. It is cheap to include a covariate, not free.

Every covariate is treated as equally important. \(M\) is invariant to rescaling, which is a virtue for units and a limitation for priorities. If some covariates genuinely matter more, use tiered rerandomization (Morgan and Rubin, 2015), which applies separate thresholds to groups of covariates in order of importance.

Keep the accepted split reproducible. Record the seed, the covariate matrix, the encoding, and the threshold. Because \(S\) is computed from the data at hand, a change in the covariate set changes the metric and therefore the accepted split.

You have $N$ units with covariate matrix $X$ ($N \times p$), and you want to
split them into two equal groups of $n = N/2$ such that the covariates are
balanced. The plan is *rerandomization*: draw a random split, measure imbalance,
and redraw if the imbalance is too large.

The measure of imbalance is a Mahalanobis distance. This article assumes the
[previous one](../mahalanobis-distance/), and in particular that $D^2 =
(x-\mu)^{\top}\Sigma^{-1}(x-\mu)$ is affine invariant, discounts correlated
columns rather than double-counting them, and handles categorical covariates
via a dropped baseline or a pseudo-inverse.

## The criterion

The natural summary of imbalance is the vector of covariate mean differences,

$$
d \;=\; \bar{X}_T - \bar{X}_C \;\in\; \mathbb{R}^p .
$$

Under complete randomization into equal halves, $\mathbb{E}[d] = 0$ and

$$
\operatorname{Cov}(d)
  = \Big(\tfrac{1}{n_T} + \tfrac{1}{n_C}\Big) S
  = \frac{4}{N}\,S ,
$$

where $S$ is the sample covariance matrix of the covariates. So $d$ is a random
vector with a known mean and a known covariance, and the obvious way to say "$d$
is too far from zero" is its Mahalanobis distance from $0$:

::: {.keybox}
$$
M \;=\; d^{\!\top}\big[\operatorname{Cov}(d)\big]^{-1} d
    \;=\; \frac{N}{4}\; d^{\!\top} S^{-1} d .
$$
:::

This is exactly the criterion Morgan and Rubin proposed in 2012. Everything from
the Mahalanobis article applies verbatim: $M$ is affine invariant (so the units
of your covariates are irrelevant and you need not standardise first),
correlated covariates are not double-counted, and categorical covariates are
handled by dropping a baseline or using $S^{+}$.

```{python}
#| label: rerand-setup

N = 200
n_T = N // 2

# Two covariates so the acceptance region can be drawn.
Xrr = rng.multivariate_normal(mu_hw, S_hw, N)
S_rr = np.cov(Xrr, rowvar=False, ddof=1)
cov_d = (4 / N) * S_rr

def draw_splits(B, N, n_T, rng):
    """B random equal splits, as a B x N matrix of +1 (treated) / -1 (control)."""
    idx = np.argsort(rng.random((B, N)), axis=1)[:, :n_T]
    s = -np.ones((B, N))
    np.put_along_axis(s, idx, 1.0, axis=1)
    return s

B = 40_000
s_mat = draw_splits(B, N, n_T, rng)
d_all = (2 / N) * (s_mat @ Xrr)                       # B x 2 mean differences
M_all = np.einsum("bi,ij,bj->b", d_all, np.linalg.inv(cov_d), d_all)

print(f"empirical Cov(d) / theoretical (4/N)S:\n"
      f"{np.round(np.cov(d_all, rowvar=False) / cov_d, 3)}")
print(f"\nmean of M : {M_all.mean():.4f}   (chi-square with p=2 has mean 2)")
```

## Choosing the threshold

Since $M$ is a squared Mahalanobis distance of an (approximately normal)
$p$-vector, $M \sim \chi^2_p$. That gives you the threshold directly. To accept
a proportion $p_a$ of draws, set

$$
a = F^{-1}_{\chi^2_p}(p_a), \qquad \text{accept iff } M \le a .
$$

The expected number of draws before acceptance is $1/p_a$. Note that
thresholding $M$ at $a$ is the same as thresholding the *distance* $\sqrt{M}$ at
$\sqrt{a}$; the squared scale is the convenient one because it is the scale on
which the $\chi^2$ table is written.

```{python}
#| label: tbl-thresholds

rows = []
for p_a_ in [0.5, 0.1, 0.05, 0.01, 0.001, 0.0001]:
    for pp_ in [2, 5, 10]:
        rows.append({"p_a": p_a_, "p (covariates)": pp_,
                     "threshold a": stats.chi2.ppf(p_a_, pp_)})
thr = pd.DataFrame(rows).pivot(index="p_a", columns="p (covariates)",
                               values="threshold a")
thr["expected draws"] = [1 / x for x in thr.index]
thr.round(3)
```

## The acceptance region is an ellipse

at the origin, and its shape is set by $S$ — it is elongated in exactly the
direction in which imbalance naturally occurs.

## Why an ellipse and not a circle

The ellipse leans along the positive correlation between height and weight,
which at first looks backwards: it is *more permissive* about splits where both
covariates are imbalanced in the same direction. That is the correct behaviour,
for the same reason correlated columns are not double-counted. Height and weight
are correlated at $0.7$, so a split that over-represents tall people will
mechanically over-represent heavy people too. Those two imbalances are largely
one imbalance, and a criterion that counted them separately would spend nearly
all its rejections fighting the most common failure mode while barely
constraining the rare, genuinely informative direction — arms that differ in
weight *given* height.

There is also a practical reason to prefer the ellipse:

::: {.keybox}
The Mahalanobis criterion accepts exactly $p_a$ of draws whatever the
correlation structure is, so you can read the threshold off a $\chi^2$ table.
The per-covariate criterion's acceptance rate depends on $S$, so its threshold
has to be calibrated by simulation every time.
:::

```{python}
#| label: naive-miscalibration

nominal = stats.chi2.ppf(p_a, 2)     # the chi-square threshold, wrongly reused
print(f"threshold from the chi-square table, a = {nominal:.4f}\n")
print(f"  Mahalanobis criterion accepts : {np.mean(M_all <= nominal):6.2%}")
print(f"  per-covariate criterion accepts: {np.mean(M_naive <= nominal):6.2%}")
print(f"  ... both should accept         : {p_a:6.2%}")
```

## How much does it buy you?

Morgan and Rubin show that rerandomizing on $M \le a$ reduces the variance of
every covariate mean difference by the same factor,

::: {.keybox}
$$
v_a \;=\; \frac{\operatorname{Var}_{\text{RR}}(d_j)}{\operatorname{Var}_{\text{CR}}(d_j)}
      \;=\; \frac{P\big(\chi^2_{p+2} \le a\big)}{P\big(\chi^2_{p} \le a\big)} .
$$
:::

The important qualitative feature is how it degrades with $p$: at a fixed
acceptance rate, more covariates means less benefit per covariate. Balancing on
twenty covariates at $p_a = 0.01$ buys much less than balancing on two.

```{python}
#| label: fig-variance-reduction
#| fig-cap: "Variance reduction factor for each covariate mean difference. Lower is better. At a fixed acceptance rate the benefit erodes quickly as covariates are added. With p = 2, accepting 1 draw in 100 leaves 0.5% of the original imbalance variance; with p = 50 the same acceptance rate leaves 55%, and going all the way to 1 draw in 1,000 only gets it to 46%."
#| fig-height: 4.2

    a_g = stats.chi2.ppf(pa_grid, pv)
    v_g = stats.chi2.cdf(a_g, pv + 2) / stats.chi2.cdf(a_g, pv)
    ax.plot(pa_grid, v_g, color=col, lw=2, label=f"$p = {pv}$")
ax.set_xscale("log")
ax.set_xlabel("acceptance probability $p_a$  (expected draws = $1/p_a$)")
ax.set_ylabel("$v_a$ vs. complete randomisation")

ax.set_ylim(0, 1)
ax.legend(ncol=3, loc="lower right")
fig.tight_layout()
plt.show()
```

Two caveats keep this honest.

**Balance is not the goal; precision is.** The variance of the treatment effect
estimator is reduced by a factor of $1 - (1 - v_a)R^2$, where $R^2$ is the
squared multiple correlation between the outcome and the covariates. If your
covariates do not predict the outcome, perfect balance on them buys you nothing.
Covariate *choice* matters more than threshold choice.

**The usual standard errors no longer apply.** Rerandomization makes the
sampling distribution of the difference in means non-normal — Li, Ding and Rubin
(2018) show it is a normal plus a truncated-normal term. A conventional
two-sample $t$-test on rerandomized data is conservative (its intervals are too
wide). Either use randomization-based inference that redraws under the *same*
rerandomization scheme, or use the asymptotic distribution from that paper.

## Doing it efficiently

Inside a rerandomization loop you will evaluate $M$ hundreds of thousands of
times, so it is worth not recomputing anything that does not change. Write
$s_i = +1$ for treated and $-1$ for control, with $\sum_i s_i = 0$. Then
$d = \frac{2}{N}\sum_i s_i x_i$, and substituting into $M$:

::: {.keybox}
$$
M \;=\; \frac{1}{N}\Big\|\sum_{i=1}^{N} s_i z_i\Big\|^2,
\qquad z_i = L^{-1}(x_i - \bar{x}), \quad S = LL^{\!\top}.
$$
:::

Whiten the covariate matrix **once**, and every draw afterwards is a sum of rows
and a squared norm — no linear solve, no covariance matrix.

```{python}
#| label: fast-path-check

Z_rr = np.linalg.solve(np.linalg.cholesky(S_rr), (Xrr - Xrr.mean(0)).T).T
M_fast = np.sum((s_mat @ Z_rr) ** 2, axis=1) / N
print(f"max |M - M_fast| = {np.abs(M_all - M_fast).max():.3e}")
```

How much does it actually matter? Honest timings on a larger problem
($N = 400$, $p = 8$, 20,000 draws), from the naive loop most people write first
down to a fully vectorised version:

```{python}
#| label: tbl-timings

import time

N_b, p_b, B_b = 400, 8, 20_000
Xb = rng.normal(size=(N_b, p_b)) @ rng.normal(size=(p_b, p_b)) + 3.0
Sb = np.cov(Xb, rowvar=False, ddof=1)
Sb_inv = np.linalg.inv(Sb)
Zb = np.linalg.solve(np.linalg.cholesky(Sb), (Xb - Xb.mean(0)).T).T
nTb = N_b // 2
Zb_tot = Zb.sum(0)

def loop_resolve():
    out = np.empty(B_b)
    for b in range(B_b):
        m = np.zeros(N_b, bool); m[rng.permutation(N_b)[:nTb]] = True
        d = Xb[m].mean(0) - Xb[~m].mean(0)
        out[b] = (N_b / 4) * d @ np.linalg.solve(Sb, d)     # refactorises S!
    return out

def loop_precomputed():
    out = np.empty(B_b)
    for b in range(B_b):
        m = np.zeros(N_b, bool); m[rng.permutation(N_b)[:nTb]] = True
        d = Xb[m].mean(0) - Xb[~m].mean(0)
        out[b] = (N_b / 4) * d @ Sb_inv @ d
    return out

def loop_whitened():
    out = np.empty(B_b)
    for b in range(B_b):
        g = 2 * Zb[rng.permutation(N_b)[:nTb]].sum(0) - Zb_tot
        out[b] = (g @ g) / N_b
    return out

def batched():
    s = draw_splits(B_b, N_b, nTb, rng)
    return np.sum((s @ Zb) ** 2, axis=1) / N_b

timings = []
for name, fn in [("loop, re-solves S each draw", loop_resolve),
                 ("loop, precomputed inverse", loop_precomputed),
                 ("loop, whitened Z", loop_whitened),
                 ("fully vectorised on Z", batched)]:
    t0 = time.perf_counter(); out = fn(); el = time.perf_counter() - t0
    timings.append({"implementation": name, "ms for 20,000 draws": el * 1000,
                    "mean M (should be ~8)": out.mean()})

tdf = pd.DataFrame(timings)
tdf["speed-up"] = tdf["ms for 20,000 draws"].iloc[0] / tdf["ms for 20,000 draws"]
tdf.set_index("implementation").round(2)
```

The gains are real but moderate, because the dominant cost is forming the mean
difference at all — that is $O(Np)$ per draw no matter what you do. The point of
the whitened form is less that it is fast and more that it makes it *impossible*
to accidentally refactorise $S$ inside the loop.

## Practical notes and failure modes

**Feasibility at small $N$.** There are only $\binom{N}{N/2}$ distinct equal
splits. That is astronomically large for $N = 200$, but for $N = 20$ it is
184,756, and an acceptance rate of $10^{-6}$ is then not merely slow but
impossible. Check $p_a \binom{N}{N/2} \gg 1$.

**More covariates is not free.** Adding a correlated covariate does not get it
extra weight in $M$, but it does raise $p$, which shrinks the variance reduction
$v_a$ available at any acceptance rate. It is cheap to include a covariate, not
free.

**Every covariate is treated as equally important.** $M$ is invariant to
rescaling, which is a virtue for units and a limitation for priorities. If some
covariates genuinely matter more, use tiered rerandomization (Morgan and Rubin,
2015), which applies separate thresholds to groups of covariates in order of
importance.

**Keep the accepted split reproducible.** Record the seed, the covariate matrix,
the encoding, and the threshold. Because $S$ is computed from the data at hand,
a change in the covariate set changes the metric and therefore the accepted
split.
